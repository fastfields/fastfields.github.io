fastfields.torch

fastfields.torch: an autograd-enabled torch interface over the bindings.

A user-friendly, autograd-enabled torch interface over the fastfields.dlpack bindings.

Public API

Differentiable (torch.autograd.Function-backed):

  • :func:sym_matvec -- mat @ vec (grad wrt mat and vec)
  • :func:sym_solve -- (mat + diag(weight)) \ vec (grad wrt vec)
  • :func:sym_solve_ -- in-place :func:sym_solve (grad wrt the mutated right-hand side; safe under autograd, see API_CONTRACT.md)
  • :func:resample -- spline prolongation (backward: restriction)
  • :func:restriction-- adjoint of resample (backward: resample)
  • :func:spline_coeff -- interpolating-coefficient prefilter

  • :func:spline_coeff_ -- in-place :func:spline_coeff (self-adjoint, safe under autograd)

  • :func:pull, :func:push -- spline gather/scatter (grad wrt the field and the sampling grid)

  • :func:count -- splat ones (grad wrt grid)
  • :func:grad -- sample spatial gradients (grad wrt the field and grid; this is the second-order term a learned deformation needs)
  • the regulariser operators: :func:field_matvec / :func:flow_matvec, their _add/_sub accumulate forms over the operator, the diagonal and the stencil, :func:field_forward / :func:field_precond and their flow twins

Not differentiable, but still exposed for parity with fastfields.numpy/fastfields.cupy: forward always runs (even when an input requires grad), and only calling .backward() through the output raises a clear RuntimeError naming the op -- see each function's docstring, and API_CONTRACT.md ("In-place policy") for why this differs from earlier revisions that omitted these ops or rejected grad-requiring inputs at call time:

  • :func:dt_euclidean, :func:dt_euclidean_
  • :func:dt_l1, :func:dt_l1_
  • :func:dt_mesh (no in-place form on any backend)
  • :func:dt_spline_table, :func:dt_spline_brent, :func:dt_spline_gaussnewton -- the value at an argmin found by an inner optimisation, which the library does not differentiate
  • :func:sym_invert, :func:sym_invert_
  • :func:sym_addmatvec_, :func:sym_submatvec_ -- differentiable wrt the accumulator, but not wrt mat/vec; the out-of-place out0 + sym_matvec(mat, vec) is differentiable wrt all three

Re-exported enums: :class:Spline, :class:Bound.

What this wrapper deliberately does not expose

Of the 58 public operations of the C++ hub, this package wraps all but nine. tools/api_inventory.py in fastfields-dlpack prints the full matrix; the omissions are:

pull_backward, push_backward, count_backward, grad_backward, sym_matvec_backward Used, not re-exported. These are the adjoints behind the autograd.Function of the corresponding forward op, which is the supported way to reach them: call :func:pull / :func:push / :func:count / :func:grad / :func:sym_matvec and .backward(). Re-exporting them as functions would mean a second, unchecked spelling of a gradient computation, with five pre-zeroed buffers and an accumulate-vs-overwrite contract for the caller to get right. fastfields.dlpack has them raw for anyone who wants that.

field_precond_, flow_precond_, field_cg In-place preconditioner solves and the CG driver. The in-place forms would have to resolve against autograd's rules for a mutated buffer (API_CONTRACT.md, "In-place policy") and field_cg runs an iterative solver whose gradient is a solve with the same operator -- both worth doing, neither a mechanical wrapper, and both separate from exposing the ops. :func:field_relax is the differentiable-free in-place solver available today; fastfields.numpy has all three.

The implementation is split by category into :mod:._util (shared helpers and CUDA-stream resolution), :mod:._dt (distance transforms), :mod:._sym (compact-symmetric linear algebra), :mod:._resample (spline coefficients and resampling/restriction), :mod:._pushpull (spline gather/scatter) and :mod:._reg (spatial regularisers).

Notes

A single mesh is queried by an arbitrarily batched point set: only loc carries batch dims, and dist (and nearest_vertex) are allocated with loc.shape[:-1]. grad 

grad(inp: Tensor, grid: Tensor, order: int | str = 2, bound: int | str = 'dct2', *, extrapolate: int = 1, abs: bool = False) -> Tensor

Sample spatial gradients of inp at grid -> (*B,*out,C,D).

Differentiable wrt inp and grid. grad is itself a derivative operator, so its adjoint contributes second-order terms -- which is the point: an image gradient computed inside a loss has to be differentiable for the deformation that produced grid to be learnable.

abs replaces the signed spline derivative by its absolute value (a majorisation trick); the backward pass is run with the same flag. Note that with abs=True the backward is the adjoint of the majorised operator, which is deliberately not the Jacobian of the forward map -- use it as the majorisation it is, not as a gradient to validate.

field_kernel 

field_kernel(ndim: int, absolute=None, membrane=None, bending=None, *, channels: int | None = None, voxel_size=None, bound: int | str = 'dct2', dtype: dtype = float64, device=None) -> Tensor

Materialise the field regulariser's per-channel Toeplitz stencil.

Returns the small centred kernel that, convolved with a field, reproduces :func:field_matvec. The shape is (*k, C) (channels are independent), with k the stencil width per spatial dim: 1 (absolute), 3 (membrane) or 5 (bending). C is channels if given, else inferred from the per-channel penalty lengths (default 1). Not differentiable.

field_matvec_rls(inp: Tensor, wgt: Tensor, absolute=None, membrane=None, bending=None, *, voxel_size=None, bound: int | str = 'dct2', ndim: int = 1) -> Tensor

RLS/JRLS-weighted variant of :func:field_matvec.

wgt has shape (*batch, *spatial, 1) for a single weight shared across all channels (JRLS), or (*batch, *spatial, C) for a genuine per-channel weight (RLS, C matching inp's channel count) -- the trailing dimension of wgt selects which mode is used. Differentiable wrt inp (wgt is treated as fixed).

field_relax 

field_relax(field: Tensor, hes: Tensor, grd: Tensor, absolute=None, membrane=None, bending=None, *, voxel_size=None, bound: int | str = 'dct2', ndim: int = 1, nb_iter: int = 1) -> Tensor

Refine field in place with nb_iter relaxation sweeps.

Solves (H + L) x = g with per-voxel compact-symmetric Hessian hes (packed C*(C+1)/2 last axis), the per-channel field regulariser L (same penalties as :func:field_matvec) and gradient grd. Not differentiable (an in-place iterative solver); field is the warm start, mutated and returned.
