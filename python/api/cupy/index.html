Every function of fastfields.cupy, with its arguments, options and exceptions. The overview explains the conventions they share and what this package needs to import.

fastfields.cupy

CuPy interface to the fastfields operators, on the GPU.

The package mirrors fastfields.numpy, but its arrays are CuPy arrays living in CUDA device memory. They reach the compiled library through DLPack, which shares the device memory instead of copying it.

Functions take CuPy arrays and return newly allocated CuPy arrays. Inputs must be float32 or float64 and are passed with their own strides, so nothing is made contiguous; outputs are allocated contiguous. Functions whose name ends in an underscore (dt_euclidean_, sym_solve_ and so on) update their first argument in place and return it.

All work is queued on CuPy's current CUDA stream: every wrapper forwards cupy.cuda.get_current_stream().ptr to the library, so the kernels are ordered with respect to the surrounding CuPy operations. To run on another stream, call the function inside a with my_stream: block.

Availability

Two things can be missing, and they are treated differently.

CuPy itself is imported lazily, so import fastfields.cupy succeeds where CuPy is not installed or there is no GPU; a clear ImportError is raised only when a wrapper is called. That keeps the static parts of the package, the enums and the argument normalisers, importable and testable anywhere.

The CUDA kernels are checked eagerly instead. import fastfields.cupy raises ImportError when the installed fastfields-dlpack is a CPU-only build, and the message names the wheel-index lane to install. Without the kernels nothing here can work, so there is no point in waiting for the first call.

What this wrapper deliberately does not expose

Of the 58 public operations of the C++ hub, this package wraps all but five.

The adjoints of the sampling operators. pull_backward, push_backward, count_backward and grad_backward give the gradient with respect to both the sampled field and the sampling coordinates. They exist so that an autograd engine can differentiate through grid, and only fastfields.torch has one. A wrapper here would be a function that nothing calls, with several pre-zeroed device buffers for the caller to get right. They remain available as fastfields.dlpack.pull_backward(...) and so on.

The conjugate-gradient solver. field_cg is CPU-only in the C++ library: its dot products need a device-side reduction that the CUDA backend does not implement yet (fastfields-lib#34), and the hub rejects CUDA arrays instead of quietly running on the host. A fastfields.cupy.field_cg could therefore only ever raise. field_relax and flow_relax run on CUDA and solve the same system by Gauss-Seidel sweeps.

tests/test_api_coverage_cupy.py fails if the set of omitted operations ever changes by accident.

Bound

Bases: IntEnum

Boundary condition, applied to every spatial axis.

Member Value Beyond the last voxel, the signal
Zero 0 is zero
Replicate 1 repeats the last voxel (coordinates are clipped)
DCT1 2 is symmetric about the centre of the last voxel
DCT2 3 is symmetric about the edge of the last voxel
DST1 4 is antisymmetric about the centre of the last voxel
DST2 5 is antisymmetric about the edge of the last voxel
DFT 6 wraps around (circular)
NoCheck 7 is not handled: coordinates are assumed inbound

DCT2 is the Neumann condition and DST2 the Dirichlet one.

The wrappers take it as the bound argument, as an integer, as a member of this enum or as a name such as "dct2"; see as_bound.

Spline

Bases: IntEnum

Order of the spline used for interpolation.

The members are the integers 0 to 7, from Nearest (0), Linear (1), Quadratic (2) and Cubic (3) up to FourthOrder, FifthOrder, SixthOrder and SeventhOrder (4 to 7).

The wrappers take it as the order argument, as an integer, as a member of this enum or as a name such as "cubic"; see as_spline. The raw fastfields.dlpack bindings and the C++ library call the same argument spline.

current_stream_ptr 

current_stream_ptr() -> int

Return the pointer of cupy's current CUDA stream.

fastfields_bind forwards its stream argument straight to the CUDA backend, so every wrapper passes this value. Because cupy queues all work on its current stream, forwarding that same stream keeps the binding's kernels ordered correctly with respect to the surrounding cupy operations (allocation of the output, later reads, etc.). Callers who want a specific stream simply wrap the call in a with stream: block.
